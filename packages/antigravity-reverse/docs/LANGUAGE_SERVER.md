## 1. Executive Summary & Architectural Overview

The core computational engine of Google Antigravity is not executed inside the Electron Chromium renderer or Node.js main process. Instead, Antigravity delegates all language model orchestration, file system operations, terminal command execution, semantic search, trajectory persistence, and upstream Google Cloud communication to an out-of-process native daemon: **`language_server.exe`**.

```

|                             (Antigravity.exe, PID 22032)                              |
|  - Spawns language_server.exe with dynamic ephemeral HTTPS port & random CSRF token   |
|  - Starts loopback HostBridge HTTP server (--host_bridge_url=http://127.0.0.1:63079)  |
|  - Manages browser window lifecycle and native OS dialogs                             |
+---------------------------------------------------------------------------------------+
                         |                                 ^
          Process Exec & |                                 | HostBridge RPC
          Env Arguments  |                                 | (UpdateStatus, ApplyUpdate)
                         v                                 |
+---------------------------------------------------------------------------------------+
|                         Language Server Native Daemon                                 |
|                       (language_server.exe, PID 27460)                                |
|                                                                                       |
|  [Connect Protocol Server]            [Agent Engine & Cortex]                         |
|   - HTTPS loopback (127.0.0.1:<PORT>)  - Go text/template prompt engine               |
```

### Key Architectural Characteristics
1. **Connect Protocol Transport:** Rather than raw gRPC HTTP/2 or standard REST, the daemon exposes the **Connect Protocol (v1)**. This allows clients to communicate seamlessly using either lightweight JSON (`application/json`) or serialized Protobuf (`application/proto`) over standard HTTPS/1.1 with self-signed loopback certificates.
2. **CSRF Authentication Barrier:** Every inbound ConnectRPC call must supply a valid `x-codeium-csrf-token` header matching the UUID generated by the Electron parent process at startup. Calls lacking this token or providing an invalid secret are rejected with `HTTP 401 Unauthorized`.
3. **Proprietary Storage Architecture (Zero `state.vscdb`):** Contrary to VS Code forks (e.g. Cursor, Windsurf), Antigravity originates from Google's internal "Jetski" application tree (`google3/third_party/jetski`). It stores state entirely in SQLite3 databases (`conversation_summaries.db` with FTS5 virtual tables and individual `<conversation_id>.db` files) and structured `brain/` workspace artifacts.
4. **Agent Client Protocol (ACP) Parity:** In addition to the GUI daemon, Google distributes `agy_acp_server.exe` as a standalone binary for the Agent Client Protocol, running over `stdin`/`stdout` JSON-RPC for headless CLI harnesses (e.g., T3 Code).

### Binary Internals Breakdown

#### 1. `language_server.exe`
- Statically links the Go runtime, Go standard library (`net/http`, `database/sql`, `crypto/tls`), Google internal Protobuf runtime, ConnectRPC handler dispatcher, and embedded SQLite3 C library (via cgo).
- Contains Google internal Blade and Stubby RPC client stubs for Googler-tier inference endpoints.
- Embeds Go `text/template` assets for system prompt assembly, subagent isolation reminders, and tool output formatting.

#### 2. `webm_encoder.exe`
- Specialized auxiliary daemon responsible for capturing screen frames from Chromium during browser subagent interactions and encoding them into WebM video clips.
- Connects to Chrome DevTools Protocol via WebSocket URL configured in `AGY_BROWSER_WS_URL` or reads the active debugging port from the file path in `AGY_BROWSER_ACTIVE_PORT_FILE`.
- Embeds command-line launch arguments for headless Chromium instances:
  `--remote-debugging-port`, `--headless`, `--user-data-dir`, `--no-first-run`, `--no-default-browser-check`, `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`, `--disable-background-timer-throttling`.

#### 3. `elevate.exe`
- Lightweight Rust-compiled Windows executable utilizing the Windows ShellExecute API (`runas` verb) to elevate subprocess permissions when installing updates or modifying system-level directories.

#### 4. `agy_acp_server.exe`
- Standalone runner implementing the open Agent Client Protocol (ACP) v1.
- Bundles `localharness_external.exe` (145.5 MB), which unpacks a hermetic Python/C++ agent orchestration environment into the system temp directory (`%TEMP%`) at startup.
- Registered under the canonical ACP registry ID `antigravity-acp` with icon URL `https://cdn.agentclientprotocol.com/registry/v1/latest/antigravity-acp.svg`.

## 5. Local Connect Protocol & CSRF Handshake

### Wire Framing & Protocol Format
Communication between clients (Electron UI, Web Hub, or headless scripts) and `language_server.exe` follows the **Connect Protocol (v1)** specification over loopback HTTPS (`https://127.0.0.1:<PORT>/...`):

- **Transport:** HTTP/1.1 POST (or HTTP/2) over TLS.
- **Certificate:** Self-signed localhost certificate generated in-memory by the language server. Client libraries must set certificate validation to ignore untrusted root CAs (e.g. `rejectUnauthorized: false` in Node.js or `verify=False` in Python).
- **Endpoint Structure:** `POST https://127.0.0.1:<PORT>/<Service_Name>/<Method_Name>`
- **Wire Serialization:** Clients can send JSON payloads (`Content-Type: application/json`) and receive JSON responses. Binary Protobuf (`application/proto` and `application/grpc-web+proto`) is also fully supported.

### Mandatory Request Headers
```http
POST /exa.language_server_pb.LanguageServerService/GetStatus HTTP/1.1
Host: 127.0.0.1:60608
Content-Type: application/json
Connect-Protocol-Version: 1
x-codeium-csrf-token: c0a1f4a7-746b-40aa-91dc-833d6b89e8cb
Content-Length: 2

{}
```

### CSRF Authentication Handshake & 401 Rejection Behavior
The language server strictly enforces token equality on every incoming request.

#### Case 1: Missing CSRF Header
If a client sends an RPC request without the `x-codeium-csrf-token` header:
- **HTTP Status:** `401 Unauthorized`
- **Response Headers:** `content-type: application/json`
- **Verbatim Body:**
  ```json
  {"code":"unauthenticated","message":"unauthenticated: missing CSRF token"}
  ```

#### Case 2: Invalid or Mismatched CSRF Token
If a client sends an invalid UUID or another session's token:
- **HTTP Status:** `401 Unauthorized`
- **Response Headers:** `content-type: application/json`
- **Verbatim Body:**
  ```json
  {"code":"unauthenticated","message":"unauthenticated: invalid CSRF token"}
  ```

#### Case 3: Successful Authentication
When supplied with the matching token from the active process command line:
- **HTTP Status:** `200 OK`
- Returns valid JSON or streaming response payload.

### Forensic Analysis of `state.vscdb`
Previous assumptions that Antigravity, like other AI code editors, stores conversation history in VS Code's `state.vscdb` are **refuted by binary and filesystem forensics**:
1. **Binary Search:** Direct byte-level regex scanning across the entire 171.4 MB `language_server.exe` binary yielded **0 occurrences** of the string `vscdb`.
2. **Filesystem Search:** A comprehensive recursive scan across `%APPDATA%\Antigravity`, `%LOCALAPPDATA%\Programs\Antigravity`, and `~/.gemini/` revealed **zero `.vscdb` files**.
3. **Forensic Conclusion:** Antigravity was engineered from Google's proprietary "Jetski" architecture (`google3/third_party/jetski`) rather than a standard VS Code workbench fork. All persistent session state is managed via proprietary SQLite schemas (`conversation_summaries.db`, `<convo_id>.db`) and `brain/` directory artifacts.

## 9. System Prompt Assembly & Rule Injection Engine

### Directory-Based Rule Discovery
The language server automatically discovers and compiles rules as the agent operates within a workspace:
1. **Directory Walking:** When a task begins in a directory, the daemon inspects that directory and recursively walks up parent directories until it reaches the Git repository root (or workspace root).
2. **Rule Filenames:** Looks for standalone `GEMINI.md` or `AGENTS.md` files. These files contain raw Markdown instructions without YAML frontmatter and apply to their residing directory and all nested child folders.
3. **Deduplication:** Rules are deduplicated by absolute file path so that inherited rules are applied exactly once per conversation turn.

### Rule Injection Format
Forensic inspection of `language_server.exe` at offset `0x3267c05` revealed the exact rule injection format string:
```text
<RULE[%[1]s]>
%[2]s
</RULE[%[1]s]>
```
- `%[1]s`: Rule identifier or filename (e.g. `user_global` or `C:\path\to\AGENTS.md`).
- `%[2]s`: Inlined Markdown content of the rule.

### Size Limits and Token Budgets
Extracted directly from the binary's internal configuration text at offset `0x3391EB2`:
1. **Per-File Size Limit (`24 KB` / `24,000` bytes):** Each rule file is capped at 24,000 bytes (after expanding `@[label](path)` includes). Any file exceeding this limit is truncated on line boundaries.
2. **Aggregate Rules Budget (`20,000` tokens):**
   - The daemon allocates a dedicated 20,000-token rules budget (`defaultRulesBudget`).
   - This budget is distinct from the customization budget for skills, subagents, and MCP tools.
   - **Demotion Behavior:** If the total size of all active rules exceeds 20,000 tokens, the daemon demotes over-budget rules from full inline text to file path pointers, instructing the agent to read the file on-demand.
   - **Builtin Exemption:** Rules bundled with built-in plugins are exempt from this budget and are always inlined in full.

### Go `text/template` Snippets

## 10. Agent Client Protocol (ACP) & Headless Execution

While `language_server.exe` serves the desktop UI and headless ConnectRPC clients, Google also distributes `agy_acp_server.exe` as the headless implementation of the open **Agent Client Protocol (ACP)**.

```
+-------------------------------------------------------------------------------+
|                       Headless Harness (e.g. T3 Code)                         |
+-------------------------------------------------------------------------------+
                                      |
                         stdio JSON-RPC 2.0 (stdin/stdout)
                                      v
+-------------------------------------------------------------------------------+
|                             agy_acp_server.exe                                |
|  - Registered as 'antigravity-acp' in official ACP registry                   |
|  - Icon: https://cdn.agentclientprotocol.com/registry/v1/latest/...           |
|  - Unpacks localharness_external.exe (145.5 MB) to %TEMP%                      |
|                                                                               |
|  Supported ACP Capabilities:                                                  |
|  - canList, canLoad, canResume, canDelete (Session persistence)               |
|  - canConfigureProviders (Dynamic model & base URL configuration)             |
|  - Multiple workspace directories (additionalDirectories)                     |
+-------------------------------------------------------------------------------+
```

### Key Differences: ConnectRPC vs. ACP
- **ConnectRPC (`language_server.exe`):** Full IDE parity, access to user quotas, 5-hour rolling limits, exact step rollback (`RevertToCascadeStep`), live trajectory databases, and embedded MCP servers. Best for deep IDE automation and headless desktop extensions.
- **ACP (`agy_acp_server.exe`):** Standardized, tool-agnostic protocol for multi-agent CLI harnesses. Communicates over `stdio` pipes, requires zero local network listening sockets, and abstracts model inference behind ACP session schemas.
