LIVE CONTROL PLANE

Aktiv & wartend

Keine laufende Operation.
1. So verhindert das System Konflikte
  1. Jeder schreibende API-Aufruf erhält eine Operation-ID.
  2. Die Control Plane reserviert Conversation, Projekt, Scheduler oder Primärfenster als Lease.
  3. Kollidierende Vorgänge warten FIFO, bis der vorherige vollständig beendet ist.
  4. Verschiedene Conversation-Fenster dürfen weiterhin parallel arbeiten.
  5. Ein Fehler gibt die Lease sicher frei; die nächste Operation startet danach.
  6. Ein Idempotency-Key verhindert doppelte Ausführung bei Retry oder Doppelklick.
2. Ordner, GitHub und Anti-Gravity als einen Projekt-Workflow anlegen
  1. Im Dashboard Projekt hinzufügen öffnen.
  2. Name, Windows-Basisordner und GitHub-Sichtbarkeit wählen; der endgültige Zielpfad wird vorab angezeigt.
  3. Projekt komplett anlegen führt lokal Git, GitHub und danach Anti-Gravity seriell aus.
  4. Der Hub übergibt denselben Ordner direkt an Add Folder; ein Explorer-Dialog muss nicht ferngesteuert werden.
  5. Bei einem Teilfehler bleibt das lokale Hub-Projekt erhalten. Fehlende Schritte können idempotent erneut ausgeführt werden.
  6. Alternativ darunter ein vorhandenes GitHub-Repository importieren und später über ⚙ zuordnen.
3. Conversations lesen, öffnen, parallel steuern und löschen
  1. Der Chats-Tab lädt aktive, projektbezogene und auf Wunsch archivierte Conversations.
  2. Solange der Tab sichtbar ist, gleicht er den Katalog alle zwei Sekunden mit Anti-Gravity ab; externe Archivierungen oder Löschungen erscheinen ohne Reload.
  3. Beim Öffnen erhält jede Conversation ein dediziertes minimiertes Fenster mit eigener ID.
  4. Nachrichten an dieselbe Conversation werden nacheinander zugestellt und verifiziert.
  5. Nachrichten an verschiedene dedizierte Fenster können gleichzeitig laufen.
  6. Beim Löschen schließt der Hub zuerst das zugehörige Fenster und entfernt danach die Conversation.
4. Scheduled Tasks vollständig fernsteuern
  1. Scheduled Tasks öffnen und native Verbindung prüfen.
  2. Name, Projekt, Rhythmus/Uhrzeit oder Cron und Prompt festlegen.
  3. Task zunächst deaktiviert speichern und Inhalt kontrollieren.
  4. Aktivieren, deaktivieren, bearbeiten, Events lesen oder löschen.
  5. Task neu starten startet den Schedulerprozess – nicht den Prompt sofort.
5. Modelle, Proxy-Modelle und Diagnose
  1. Native Modelle über /api/antigravity/models lesen. Die Liste stammt dynamisch aus der sichtbaren Combobox oder dem Anti-Gravity-Language-Server.
  2. Neue native Modelle wie Gemini 3.6 erscheinen ohne Hub-Codeänderung; statische Modelllisten werden nicht verwendet.
  3. Aktives Modell über /api/antigravity/active-model setzen.
  4. Eigene OpenAI-kompatible Modelle unter /api/antigravity/custom-models verwalten und testen.
  5. Bei Problemen zuerst /health und danach /api/control-plane/operations prüfen.
  6. Die Operation-ID mit logs/control_operations.jsonl abgleichen.
6. Vollständiges API-Handbuch lesen
