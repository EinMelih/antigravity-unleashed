Antigravity Web API v2.1

Nutze dein Antigravity-Abo als vollständige OpenAI-kompatible REST-API. Kein externer API-Key nötig.

🔑 Authentifizierung

Alle API-Endpoints (außer /health und /) erfordern einen Auth-Token:

Authorization: Bearer ag-local-token
# ODER
X-Api-Key: ag-local-token

Multi-Key Auth

Für Produktionsumgebungen können mehrere Keys mit individuellen Rate-Limits konfiguriert werden:

"api_keys": {
  "EXAMPLE_PROD_TOKEN_DO_NOT_USE": { "name": "Production", "rpm": 60 },
  "EXAMPLE_DEV_TOKEN_DO_NOT_USE":  { "name": "Development", "rpm": 5 }
}

⚡ SSE Streaming

Setze "stream": true im Request für Echtzeit-Antworten im OpenAI-Chunk-Format:

data: {"id":"chatcmpl-xxx","choices":[{"delta":{"role":"assistant"},"finish_reason":null}]}
data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"Hallo"},"finish_reason":null}]}
data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"!"},"finish_reason":null}]}
data: {"id":"chatcmpl-xxx","choices":[{"delta":{},"finish_reason":"stop"}]}
data: [DONE]

Die Bridge pollt das DOM alle 300ms und sendet Deltas. Nach 3s Stabilität → finish_reason: "stop".

🛡️ Rate Limiting

Aktivierbar in config.json. Response-Headers bei aktivem Limiting:

HeaderBeschreibung
X-RateLimit-LimitMax. Requests pro Minute
X-RateLimit-RemainingVerbleibende Requests
Retry-AfterSekunden bis zum nächsten erlaubten Request (bei 429)

❌ Fehlerbehandlung

Alle Fehler folgen dem OpenAI-Format:

{
  "error": {
    "message": "Beschreibung des Fehlers",
    "type": "authentication_error | invalid_request_error | rate_limit_error | internal_error"
  }
}
StatusTypUrsache
400invalid_request_errorLeere Nachricht, ungültiges JSON, zu lang
401authentication_errorFehlender oder ungültiger Token
429rate_limit_errorRate-Limit überschritten
500internal_errorServer-/CDP-Fehler
503connection_errorCDP nicht verbunden

API Bridge · Port 8001

GET / Service-Info & Quickstart ▶

Auth

Nicht erforderlich

cURL
curl http://127.0.0.1:8001/
POST /v1/chat/completions OpenAI-kompatibel + Streaming ▶
Beschreibung

Sendet eine Chat-Nachricht im OpenAI-Format. Unterstützt stream: true für SSE-Streaming.

Auth

Bearer Token erforderlich

Request Body
{
  "model": "antigravity",
  "messages": [
    { "role": "user", "content": "Hallo!" }
  ],
  "stream": false,
  "timeout": 120,
  "new_chat": false
}
Response (Normal)
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "choices": [{
    "message": { "role": "assistant", "content": "Hallo! Wie kann ich helfen?" },
    "finish_reason": "stop"
  }],
  "usage": { "prompt_tokens": 2, "completion_tokens": 7, "total_tokens": 9 }
}
cURL
curl -X POST http://127.0.0.1:8001/v1/chat/completions \
  -H "Authorization: Bearer ag-local-token" \
  -H "Content-Type: application/json" \
  -d '{"model":"antigravity","messages":[{"role":"user","content":"Hi!"}]}'
Request Body

GET POST /api/stats Token-Verbrauch abfragen & buchen ▶
Beschreibung

GET: Ruft den akkumulierten Token-Verbrauch und die geschätzten Kosten der aktuellen Session ab. Wird vom Live-Widget im Browser genutzt.

POST: Erlaubt es externen Client-Anwendungen, manuell verbrauchte Tokens (z. B. aus clientseitigen Chats) in die Session-Statistiken einzubuchen.

Request Body (nur für POST)
{
  "prompt_tokens": 15,
  "completion_tokens": 35,
  "model": "claude-sonnet-4.6"
}
Response
{
  "session": {
    "total_requests": 42,
    "total_tokens": 23600,
    "total_prompt_tokens": 5200,
    "total_completion_tokens": 18400,
    "requests_by_model": { "antigravity": { "requests": 42, "tokens": 23600 } }
  },
  "uptime_seconds": 3600
}
